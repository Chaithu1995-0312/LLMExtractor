# 1️⃣ FINITE-STATE ARCHITECTURE MAP

JARVIS UI is **4 concurrent state machines**, not one.

---

## 🧩 A. Global System State Machine

Represents overall cognitive health.

```
BOOTING
  ↓
READY
  ↓
DEGRADED  ← (LLM offline, DB lock risk)
  ↓
CRITICAL  ← (Graph DB failure)
  ↓
RECOVERING
  ↓
READY
```

### Triggers

* WebSocket health stream
* Heartbeat timeout
* AlertManager events
* Governance violations

This drives:

* Top status strip
* Global glow color
* Disabled interactions

---

## 🧠 B. Cognitive Engine State Machine

Represents backend processing lifecycle.

```
IDLE
  ↓
SYNCING
  ↓
COMPILING
  ↓
SYNTHESIZING
  ↓
IDLE
```

Parallel transitions allowed:

* SYNTHESIZING + STREAMING
* COMPILING + LOGGING

UI must treat each as independent bit flags, not exclusive states.

---

## 🧬 C. Graph Node Lifecycle State Machine

This mirrors backend invariants.

```
LOOSE
  ↓
FORMING
  ↓
FROZEN
  ↓
SUPERSEDED
  ↘
   (immutable)
```

Illegal:

```
FROZEN → KILLED
SUPERSEDED → KILLED
```

Frontend must validate before dispatching mutation.

Each node instance = independent FSM.

---

## 📡 D. Stream State Machine (Append-Only)

For logs and token streams.

```
CONNECTED
  ↓
STREAMING
  ↓
BUFFERING
  ↓
RESYNC_REQUIRED
  ↓
RECONNECTED
```

Triggers:

* WebSocket disconnect
* Event ID mismatch
* Sequence gap

If gap detected → request `GRAPH_RESYNC_DELTA`.
